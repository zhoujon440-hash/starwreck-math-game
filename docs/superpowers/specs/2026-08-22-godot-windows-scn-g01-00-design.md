# Godot Windows 原生版 SCN-G01-00 技术样板设计

## 1. 决策与目标

本设计建立《星骸拾荒者：十二星门》的新正式运行时方向：**Godot Windows EXE 原生游戏**。当前 Vite + TypeScript / HTML5 PWA 版本冻结为功能与内容验证原型，不再作为正式产品体验继续迭代。

第一阶段不是迁移全部 11 个试玩场景，而是完成一个 15–25 分钟可独立试玩的 `SCN-G01-00 · 拾光号熄灯` Vertical Slice，用它回答唯一产品问题：**玩家是否已经感觉自己在玩一个正常的原生解谜游戏，而不是在操作网页或点击任务列表。**

本阶段仅交付 Windows x86_64 EXE，不做 Web export，不做 Android/iOS，不迁移 SCN-G01-01 以后场景。

## 2. 技术基线

- Engine: Godot `4.7.2-stable` Standard，GDScript 2.0。
- Renderer: Forward+，2D 场景为主，不开发实时 3D 自由移动。
- Target: Windows 10/11 x86_64。
- Design resolution: 1920×1080；必须兼容 1366×768。
- Runtime networking: none。游戏运行时不得依赖 CDN 或远程接口。
- Save format: JSON，`schema_version: 1`，保存于 `user://save_01.json`。
- Existing Web save schema v2 不要求二进制兼容；只要求概念字段可映射，并在迁移文档中列出对应关系。
- Existing Web branch/PR #21 保持冻结；不得在该 PR 上继续做正式产品交互整改。

## 3. 仓库与代码边界

新运行时放在同一仓库的 `godot/` 子目录，以便继承现有剧情、物品、美术和验收资料，但不与 Web runtime 混写。

`godot/AGENTS.md` 对 `godot/` 子树做局部覆盖：Godot 4.7.2 + GDScript 是这里的正式运行时；根目录 Web 工程规则仅继续约束旧原型。

Godot 代码不得 import/execute TypeScript。需要继承的数据必须转成 Godot 可直接读取的 JSON/Resource，并在 `godot/data/source_mapping.json` 标记来源。

## 4. 美术继承原则

第一阶段不重新设计世界观、美术风格、角色身份和场景构图。优先继承当前已经通过验收的场景与物品资产：

- `public/assets/g01-cockpit-cabinet-closed-v2.png`
- `public/assets/g01-cockpit.png`
- `public/assets/g01-maintenance-cabinet-v2.png`
- `public/assets/items/ITM-G01-001-layer-v2.png`（应急手灯）
- `public/assets/items/ITM-G01-002-layer.png`（临时保险丝）
- `public/assets/items/ITM-G01-003-layer.png`（旧扳手）
- `public/assets/items/ITM-G01-004-layer.png`（本场景作为绝缘手套视觉复用）
- `public/assets/items/ITM-G01-005-layer.png`（本场景作为线号标签视觉复用）

Godot 项目内可以复制上述资产到 `godot/assets/inherited/`，但必须用 `godot/data/asset_provenance.json` 记录源路径、源 commit、SHA-256 和目标路径；不得悄悄重绘后仍标记为继承资产。

允许新增的内容仅限：Godot UI primitive、粒子、shader、程序化发光/遮罩、音效占位提示音（若确有本地可用来源）。不得用未经登记的第三方网络图片或音频。

## 5. 新的核心玩法循环

正式主循环冻结为：

`探索场景 → 观察异常 → 收集线索 → 在线索板建立关系 → 形成推理结论 → 找物/组合 → 回到实体设备 → 根据推论操作机关 → 世界状态变化 → 剧情反馈`

禁止退化为：

- `看到机关 → 点正确按钮 → 完成`
- `收集所有物品 → 自动告诉答案`
- `打开谜题面板 → 从若干答案中选一个`
- `拖卡片到预先写好正确答案的槽位`
- 用任务清单逐条暴露正确操作顺序。

## 6. SCN-G01-00 剧情保持与重构

现有正式剧情核心保持：拾光号突然断电；应急红光仍在闪烁；星宇需要恢复领航舱应急照明并追踪船尾失联信号。现有 `ITM-G01-001 应急手灯` 与 `ITM-G01-002 临时保险丝` 继续为关键道具，错误使用不得消耗。

但现 Web 流程：

`找手灯 → 照配电盒 → 搜维修柜 → 装保险丝 → 旋转电路 → 完成`

升级为推理型流程：

1. 玩家进入近乎全黑的领航舱，只能依靠周期性红色应急灯和局部环境光判断空间。
2. 找到并拾取应急手灯；手灯成为鼠标跟随/方向照明工具，而不是背包里点击“使用”的普通按钮。
3. 玩家用手灯主动检查多个现场对象，获得不同类型的证据。
4. 维修柜可被打开，玩家找到临时保险丝，同时看到旧扳手、绝缘手套、旧线号标签等干扰/环境信息。
5. 当至少取得必要证据后，玩家可打开“线索板”，把证据建立逻辑关系。
6. 推理板形成中间结论，而不是直接给最终按钮顺序。
7. 玩家根据自己得到的推论回到配电箱近景，完成实体操作。
8. 正确修复后，灯光不是弹字“完成”，而是舱内灯带逐段点亮、配电箱状态改变、低频设备重新工作，并出现船尾回波。
9. 样板在“船尾回波出现 / 通往导航核心舱的门被点亮”处结束，不进入 SCN-G01-01。

## 7. 线索与推理设计（16+）

### 7.1 线索集合

第一关至少包含 7 条可记录线索，其中 5 条构成主要推理，2 条具有干扰或过时信息属性。

**CLUE-001 应急灯仍周期闪烁**
- 来源：进入场景即可观察，但需用手灯照到电源状态条才能正式记录。
- 信息：主储能并非完全失效；至少存在可用的应急电源。

**CLUE-002 B 支路熔断口有新鲜烧蚀**
- 来源：手灯检查配电盒。
- 信息：B 支路近期发生过异常过流/短路。

**CLUE-003 故障记录最后一次浪涌来自 B 支路**
- 来源：配电盒侧边机械记录窗/本地诊断纸带。
- 信息：事故前最后一次异常与 B 支路吻合。

**CLUE-004 备用耦合铭牌：A↔C 仅在 B 隔离时允许闭合**
- 来源：配电盒内盖铭牌。
- 信息：给出安全恢复的结构约束，但不直接给完整操作顺序。

**CLUE-005 临时保险丝规格匹配备用耦合槽**
- 来源：维修柜，取得 `ITM-G01-002` 后观察。
- 信息：保险丝并不是拿来替换烧焦的 B 支路，而是用于备用耦合槽。

**CLUE-006 旧手写标签：‘B→C 可临时带灯’**
- 来源：维修柜旧线号标签。
- 属性：干扰线索。
- 信息：看似支持继续使用 B 支路。

**CLUE-007 改装标记：Rev.3 已取消 B→C 旁路**
- 来源：维修柜门内侧/配电箱维护贴纸。
- 属性：用于否定过时线索。
- 信息：CLUE-006 已经过时，不应采用。

### 7.2 推理关系类型

线索板不是固定答案槽位。玩家把线索卡拖入自由画布，通过连接端点建立关系，并从三种关系中选择：

- `supports` 支持
- `contradicts` 否定/冲突
- `supersedes` 新信息取代旧信息

错误连线可以删除，不扣资源；系统只用轻微“逻辑不稳定”反馈，不显示正确答案。

### 7.3 必须形成的中间结论

**DED-001 储能系统仍有可用电源**
- 需要：CLUE-001。

**DED-002 B 支路是故障支路，应保持隔离**
- 需要：CLUE-002 supports CLUE-003。

**DED-003 旧 B→C 维修建议已经失效**
- 需要：CLUE-007 supersedes CLUE-006。

**DED-004 应通过备用 A↔C 耦合恢复照明**
- 需要：DED-001 + DED-002 + DED-003 + CLUE-004 + CLUE-005。

最终 DED-004 只说明“原则”：隔离 B、使用备用保险丝、通过 A↔C 恢复，不显示机关每个控件的点击顺序。

## 8. 配电机关：实体操作而非网页谜题

机关在场景中的配电箱近景内完成，不出现居中的通用题目窗口。

至少包含四类实体控件：

1. **B 支路隔离拉杆**：可上下拖动，具有机械卡位。
2. **备用保险丝槽**：玩家从背包直接拖 `ITM-G01-002` 到真实槽位，正确时磁吸入位。
3. **A↔C 耦合旋钮**：鼠标拖动旋转，必须达到物理卡位角度。
4. **总保护开关**：玩家最后拉下/合上完成通电。

正确逻辑：

`B 隔离 → 临时保险丝进入备用槽 → A↔C 耦合对准 → 合上保护开关`

但 UI 不显示这行顺序。

错误处理：

- B 未隔离时试图耦合：局部继电器抖动、红灯、轻微电弧视觉，耦合旋钮弹回；已获得线索和已正确安装物不丢失。
- 保险丝放错槽：物体弹回背包/原位置，不消耗。
- 过早合保护开关：保护开关自动跳回，并用设备状态灯提示“回路不稳定”，不弹“答案是……”文字。
- 连续失败不得重置已完成推理图。

## 9. 手灯、探索与场景感

应急手灯必须是可感知的游戏工具：拾取后提供局部 Light2D / shader spotlight，随鼠标或右摇杆方向移动；只有被照亮到一定阈值的细节热点才显示轻微轮廓反馈。禁止满屏圆点或高亮框。

现场对象采用 `Area2D + CollisionShape2D`；鼠标悬停只提供世界内反馈（轮廓、光泽、轻微声音/光点），不显示网页按钮样式。

## 10. 线索板 UI

线索板是允许存在的系统 UI，但视觉应像飞船维修推理工作台，而不是表单页面。

- 打开时暂停世界交互但保留背景模糊/暗化。
- 左侧只列已发现证据缩略卡；中央是自由推理画布。
- 卡片可拖动、缩放位置、连线。
- 关系选择用小型径向/浮动控件，非大型下拉框。
- 新结论以“推论卡”在画布中生成，并可继续参与后续推理。
- 未发现线索绝不在板中显示灰色占位，以免泄露数量和答案。

## 11. 游戏状态与存档

`GameState` 至少保存：

- `scene_id`
- `scene_phase`
- `inventory_item_ids`
- `observed_clue_ids`
- `deduction_edges`
- `unlocked_deduction_ids`
- `installed_item_ids`
- `device_state`
- `world_state`
- `elapsed_seconds`

关键道具错误操作不消耗；正确证据、正确推论和正确机关步骤在读档后保持。

保存触发：取得关键道具、解锁推论、机关正确步骤、场景完成。

## 12. Godot 组件边界

- `GameState.gd`: 单一运行时状态与序列化入口。
- `SaveService.gd`: 只负责 JSON 持久化/迁移/损坏恢复。
- `SceneDirector.gd`: 场景阶段、相机、世界反馈流程。
- `ClueService.gd`: 发现线索、去重、解锁规则。
- `DeductionGraph.gd`: 纯逻辑图，不负责 UI。
- `DeductionBoard.gd`: 线索板输入与视觉。
- `InventoryService.gd`: 道具获得、错误使用不消耗、安装状态。
- `FlashlightController.gd`: 手灯方向与照明判定。
- `PowerPanelPuzzle.gd`: 配电设备状态机，只接受明确动作，不知道剧情 UI。
- `SCN_G01_00.gd`: 只编排本场景，不承载通用系统实现。

## 13. 数据驱动

`godot/data/scenes/scn_g01_00.json` 保存本场景的文本、线索、推理规则、热点元数据和机关参数。正式数据来源映射必须记录现 Web 的：

- `src/content/g01.ts`
- `src/data/trial/sceneExperiences.ts`
- `src/data/trial/items.ts`

不得直接运行 TS；允许 Codex 写一次性转换/核对脚本，但最终 Godot runtime 只依赖 Godot 项目内数据。

## 14. 试玩时长与难度目标

首次无攻略玩家目标时长：15–25 分钟。

设计目标不是让玩家“难在找像素”，而是让玩家经历至少一次：

1. 看到互相矛盾的信息；
2. 通过改装标记判断某条维修建议过时；
3. 把两条故障证据合并定位 B 支路；
4. 得出备用 A↔C 恢复原则；
5. 回到实体机关验证推论。

## 15. 验收标准

产品验收必须同时满足：

1. 双击 Windows EXE 可启动，不需要浏览器、Node、开发服务器。
2. 主线过程不存在 HTML/DOM/WebView。
3. 从新游戏到样板结束可完整运行。
4. 玩家至少需要建立 3 条有效证据关系并形成 4 个推论，不能只靠拾物和连续点击完成。
5. 两条干扰/过时信息真实存在，且可通过证据排除。
6. 配电机关所有关键动作在场景设备上完成。
7. 错误操作有世界反馈，但不直接泄露答案、不消耗关键道具、不清空正确进度。
8. 正确完成后必须产生明显世界变化：灯光恢复、设备状态变化、船尾回波/出口反馈。
9. 退出重进可从最近保存节点继续。
10. 1920×1080 和 1366×768 均无裁切关键控件。
11. 不进入 SCN-G01-01，不开发 G02/G03 或其他后续内容。
12. 提供 Windows release ZIP、SHA-256、至少一段完整 15–25 分钟真实试玩录像，另提供 3 段短录像：探索取证、线索板推理、配电机关操作。

## 16. 本阶段明确不做

- 不迁移其余 10 个试玩场景。
- 不做 Web export。
- 不做移动端。
- 不做实时 3D 自由移动。
- 不新增战斗、血量、敌人 AI。
- 不重写世界观和人物设定。
- 不以“所有测试通过”替代项目负责人亲自试玩的产品验收。
