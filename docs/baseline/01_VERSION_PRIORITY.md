# 版本优先级与历史资料隔离规则

## 有效基线顺序

| 优先级 | 资料 | 用途 |
|---|---|---|
| P0 | G01—G13整合正式包 V3.0 | G01序章、G02边界、总索引与全局变更 |
| P1 | G02—G13数据级制作脚本 V2.1 | 场景、热点、HOS、背包、对白、状态、提示、存档、变量、资产映射 |
| P2 | G02—G13 HOPA实施脚本 V2.0 | 章节剧情、玩家操作链、非战斗化实施 |

| P4 | 人物V2.1、场景V1.0、道具V3.0、FX/MECH/DANGER/UI V2.0 | 视觉和资产ID事实源 |
| Archive | 更早小说稿、战斗稿、Unity工程稿 | 只做历史参考 |

## 冲突处理

1. 高优先级资料覆盖低优先级资料。
2. 旧文档中的“小砾”统一映射为“星宇”，但不得修改历史原件。
3. 旧文档中的Boss战、攻击、血量、伤害、敌人AI、动作追逐等内容，若与HOPA冻结基线冲突，一律视为废弃表达。
4. Unity数据级制作脚本保留ID、字段和流程信息；当前实现必须转换为HTML5/PWA数据，不得直接宣称Unity可导入。
5. 美术总览板和三视图板为设计基线；运行时资产必须另行切制和验收。
6. 任何无法自动判定的冲突写入`docs/baseline/CONFLICTS.md`，不得由Codex自行选择版本。

## 分支规则

- `main`：已通过负责人验收的冻结基线和可运行代码。
- 基线导入任务：`codex/project-baseline-import-v1`。
- 角色剧情任务：在基线PR合并后创建`codex/g01-character-story-v1`。
- 禁止在未合并基线前并行生成新角色美术或重写剧情。

低优先级资料自动填补。
