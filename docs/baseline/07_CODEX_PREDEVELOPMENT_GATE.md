# Codex开发前置门

任何新功能、角色、场景或剧情任务开始前，Codex必须逐项确认并在PR中给出证据。

## A. 资料读取

- [ ] 已读取`00_SOURCE_OF_TRUTH.md`；
- [ ] 已读取`01_VERSION_PRIORITY.md`；
- [ ] 已读取`02_HOPA_ARCHITECTURE.md`；
- [ ] 已读取`04_ART_DIRECTION_MASTER.md`；
- [ ] 已读取对应角色冻结说明；
- [ ] 已读取对应章节最新脚本和数据；
- [ ] 已读取前后章节交接规则。

## B. 版本与命名

- [ ] 主角统一为星宇；
- [ ] 运行时和当前文档中没有“小砾”；
- [ ] G01不增加星核；
- [ ] 未引用被新版本替代的Boss/战斗/Unity限定方案；
- [ ] MECH、DANGER、UI、FX和角色ID未重编号。

## C. 美术

- [ ] 已找到冻结三视图或对应设计板；
- [ ] 已输出角色/场景特征锁定表；
- [ ] 运行时资产是切制和适配，不是重新设计；
- [ ] 未使用文字方框、emoji、圆点或占位图作为正式资产；
- [ ] 资产来源和处理步骤已记录。

## D. HOPA玩法

- [ ] 交互发生在场景图内；
- [ ] 热点默认不可见；
- [ ] 找物不是按钮网格；
- [ ] 拾取后有画面变化；
- [ ] 错误使用关键道具不消耗；
- [ ] 危险失败返回安全节点；
- [ ] S0—S6状态、存档和读档一致。

## E. 剧情

- [ ] 对白来自数据文件，不硬编码在视图；
- [ ] 角色身份、语气和关系符合冻结脚本；
- [ ] 场景目标、情绪点和下一场景一致；
- [ ] 首次关键剧情、已读跳过和历史记录规则明确；
- [ ] G01→G02不重复七码恢复和基础教学。

## F. 技术

- [ ] 当前实现保持HTML5/PWA；
- [ ] 数据结构可扩展到G01—G13；
- [ ] 有Vitest、Playwright和CI；
- [ ] 有1366×768与1920×1080验收；
- [ ] 控制台错误为0；
- [ ] 正式UI不泄露内部状态码、schema或开发文字。

## 阻断规则

任一项无法确认时，任务必须标记BLOCKED，并把缺失资料写入Issue。Codex不得自行补造世界观、角色造型、剧情或资产编号。
