# 一、开发原则

先验证完整闭环，再扩展内容；任何阶段都必须有可运行、可保存、可回退的结果。

同一系统只实现一次，通过数据配置服务多个地点、任务和星球。

先灰盒、后代表性资源、再正式资源；不在玩法未验证前追求高精度资产。

AI负责加速，不替代冻结决策、数学正确性和最终验收。

每个工作包都必须有输入、输出、验收、失败回退和依赖，不接受“先做出来看看”的无边界任务。

完整 G02 通过前，不启动第二星球正式制作。

# 七、时间与工作量规划

建议以“有效工时”管理，而不是承诺固定日历日期。以下为独立开发的规划区间，用于控制范围，不是商业报价。

| 阶段 | 建议有效工时 | 重点 | 可压缩方式 |
| --- | --- | --- | --- |
| D0资料确认 | 20—40小时 | 阅读、决策、冲突清零 | 集中评审，不新增功能 |
| M0工程骨架 | 60—100小时 | 基础架构、数据、存档、测试、构建 | 严格复用已冻结DEV规格 |
| M1最小闭环 | 60—100小时 | L00灰盒和一个数学玩法 | 全占位资源 |
| M2核心循环 | 100—160小时 | L01—L02与资源系统 | 减少正式演出 |
| M3中段内容 | 140—220小时 | L03—L08和豆包事件 | 模块化场景与复用动画 |
| M4终局 | 100—160小时 | 五塔、Boss、世界改变 | 先完成逻辑再强化表现 |
| M5/M6发布 | 120—220小时 | 正式资源、测试、修复和打包 | 优先关键画面和可用性 |

按每周15—20个有效工时，完整G02大约需要8—12个月；按每周25—35个有效工时，大约需要5—8个月。实际时间主要取决于正式美术和内容装配，不取决于文档数量。

# 九、AI协作操作规则

一个任务只交付一个可验收工作包，避免让Codex一次性完成整个游戏。

每个代码任务必须附上上游文档编号、输入数据、文件范围、测试和不允许修改项。

每个资产任务必须附上尺寸、镜头距离、材质、骨骼、命名、源文件和导出要求。

任何AI输出先进入候选区，通过人工确认后才能进入冻结资料或正式资源目录。

错误优先补测试、数据校验和工具，不靠反复提示词人工修补同类问题。

# 十、风险与控制

| 风险 | 早期信号 | 控制措施 |
| --- | --- | --- |
| 范围膨胀 | 同时讨论第二星球、移动端、联网 | Gate E1前只做G02 |
| 过度工程化 | 为了未来十二星球提前建立复杂服务 | 每个模块必须服务当前G02用例 |
| 资源制作拖延 | 玩法未验证就反复改人物和场景 | A1灰盒→A2代表性→A3正式 |
| AI代码不可维护 | 一次提交大量无测试代码 | 小工作包＋测试＋代码审查＋回滚 |
| 数学变成答题 | UI直接出现题目和四选一 | 使用世界对象和操作反馈 |
| 年龄表达失衡 | 为六年级把对白和主题幼儿化 | 沿用15—18岁表达基线，只降低操作负担 |
| 资料与实现漂移 | 代码绕过冻结规则 | 需求追踪矩阵＋变更单＋构建报告 |
