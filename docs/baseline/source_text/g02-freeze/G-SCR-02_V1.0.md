# 一、本册体验目标

| 目标 | 玩家体验 | 验收信号 |
| --- | --- | --- |
| 危机从广播变成可操作事件 | 在尾索扫荡中先判断救援顺序，再执行移动和瞬移 | 玩家能说明为什么先救人/稳住供暖箱 |
| 认识豆包与阿铆 | 豆包先作为会行动、会害怕、会帮助人的居民出现；阿铆因星宇的冲动保持警惕 | 玩家不会把豆包理解为“第五块电池” |
| 把归属做成玩法 | 修复电视墙，依据痕迹、记录和用途判断私人/公共/借用/废弃 | 玩家能给出至少两条归属依据 |
| 建立背包与交易边界 | 拾取不等于拥有；出售时看数量、单价、总价和保障量 | 玩家不误卖主线/公共资源 |
| 完成第一项工坊循环 | 出售有限废料→购买/保留材料→完成一次可恢复维修或组合 | 玩家理解工具有来源和成本 |
| 开放中段调查 | 图纸墙显示四条调查支路与磁力手套缺失模块 | 结尾自然进入SCR-03 |

# 三、逐场景制作脚本

## 3.1 S01-02｜尾索扫向供暖箱

| 字段 | 制作要求 |
| --- | --- |
| 进入条件 | 承接SCR-01：已听到居民呼救；Task.M02.Activated=True。 |
| 场景构图 | 固定广角同时显示：公共供暖箱、两名居民、红色尾索扫描面、三条可达路线。 |
| 玩家目标 | 在尾索锁定前稳定供暖箱并救出两名居民；不要求一次完美完成。 |
| 主要交互 | 先扫描三处风险；可先推开供暖箱、拉居民或瞬移切断尾索挂点。 |
| 关键状态 | Task.M02.RescuePhase；PublicHeatBox.Stabilized；Resident.RescuedCount。 |
| 失败/恢复 | 尾索拖走目标或玻璃滑坡命中→0.8秒后果→回安全棚外检查点；已完成救援对象保留。 |

### 镜头与声音

尾索接近使用红光扫描面、金属拉索声和地面振动三重预警；固定镜头不摇晃。

### 对白与声音

| 说话者/触发 | 文本 |
| --- | --- |
| 星宇｜看到尾索 | 先把人拉开。箱子别让它翻。 |
| 七码 | 两个人，一只箱子，三条路线。终于有一道题不肯排队。 |
| 阿铆｜远处 | 别碰红线！它会把你也登记成废料！ |
| 星宇｜扫描后 | 左边先落玻璃。先走中路，再回头稳箱子。 |

### 数学与认知设计

这是MT-C路径调度的第一次正式使用。玩家比较“尾索抵达时间、路线长度、玻璃雨风险、供暖中断后果”，目标是找到可行顺序而非精确算秒。辅助层在地面显示先后脉冲；挑战层只保留轨迹、声音和阴影。

### UI与提示

任务栏仅显示“救出居民，稳住供暖箱”。不显示固定步骤。每完成一项，目标文本改为剩余事项。

## 3.2 S01-03｜玻璃雨沟与第二名居民

| 字段 | 制作要求 |
| --- | --- |
| 进入条件 | 至少救出一名居民；另一名被尾索拖向玻璃雨沟。 |
| 场景构图 | 雨沟斜坡、碎屏滑流、两处瞬移锚点和一条安全绳同屏。 |
| 玩家目标 | 判断“短而危险”与“长而稳定”两条路线，救回居民并取得尾索刮痕证据。 |
| 主要交互 | 观察滑坡周期；选择路线；拉安全绳；尾索节点可短暂扫描。 |
| 关键状态 | Evidence.TailScratch.Seen；Resident.RescuedCount=2；HZ-02.Completed。 |
| 失败/恢复 | 滑落或被尾索击中→回雨沟入口；重复失败后预警窗口扩大，不自动指路。 |

### 对白与声音

| 说话者/触发 | 文本 |
| --- | --- |
| 七码 | 短路三次滑坡，长路一次尾索。你想怕哪一种？ |
| 星宇 | 先看它们是不是同一个节拍。 |
| 居民｜获救 | 那条尾巴只认标签。它没看见我在用这把工具。 |
| 星宇 | 它看见了物品，没看见关系。 |

### 数学与认知设计

两条路线都可完成。标准路线以“每三次碎屏滑落出现一次尾索横扫”为规律；玩家可利用共同安全窗口。数学重点是周期、优先级与风险比较，不要求输入数字。

### UI与提示

失败反馈只显示滑落/拖拽后果。辅助层允许在第二次失败后显示节拍光；挑战层保持纯环境线索。

### UI与提示

豆包首次出场不显示电量条，不出现“电池”关键词。角色信息卡只写“旧屏幕谷居民／维修助手”。

| 字段 | 制作要求 |

### 对白与声音

| 说话者/触发 | 文本 |
| --- | --- |
| 七码 | 这面墙还记得东西。只是它把一半记忆显示在裂缝里。 |
| 阿铆 | 能修就修。别为了看字把供暖再断一次。 |
| 星宇｜检查烧痕 | 这两根线不是同时烧的。后接的那根才是故障。 |

| 阿铆 | 先把能写进去的写对。 |

### 数学与认知设计

MT-B参数诊断入门：用烧痕新旧、屏幕闪烁周期和电容容量三个证据排除错误线路。辅助层把三类证据列入观察栏；标准层仅标记“还有未验证证据”；挑战层加入一条无关旧线路。

### UI与提示

修复界面不显示答案连线。每次验证只反馈屏幕稳定度、温度和是否保留档案；失败后可立即重试。

| 说话者/触发 | 文本 |
| --- | --- |
| 星宇 | 标签看不清，不代表没人用。 |

### UI与提示

扫描器使用图标＋文字＋纹理，不只靠颜色。分类完成后显示完整证据链，可在档案中回看。

### UI与提示

确认框用完整账目而不是“确定/取消”空提示。回购页显示原卖价、回购价和价差。
