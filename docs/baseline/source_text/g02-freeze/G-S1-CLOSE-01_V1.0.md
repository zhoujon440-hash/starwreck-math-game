# 三、跨册一致性冻结

| 主题 | 唯一有效规则 | S2设计要求 |
| --- | --- | --- |
| 主角 | 星宇：行动快、敢承担风险，但根据证据修正判断 | 不做低幼Q版；轮廓需体现探索、维修与短距瞬移能力 |
| 搭档 | 七码：冷幽默、分析和寻路，提供证据但不自动选择 | 视觉上与星宇形成功能互补，不做万能提示精灵 |
| 资源主题 | 拾取不等于拥有；借用包含用途、期限、撤回与归还 | 所有资源/UI图标需能区分来源、归属与授权状态 |
| 数学表达 | 嵌入仪表、配比、损耗、阈值、路线和调度，不做独立试卷界面 | UI优先表现关系和后果，不使用红绿判题 |
| 豆包 | 居民/协作者，不是第五电池；三种决定均可通关 | 不得做成道具电池造型或牺牲奖励 |
| Boss | B0—B7非血量权限对抗，B6固定12秒连续操作 | 不出现传统血条；必须支持五权限环和三通道HUD |
| 结局 | 狰规则更新但不被摧毁；至少六处世界变化并完成归还 | 场景需预留通关前/后状态和维修臂转化 |
| 教育反馈 | 能力证据和过程回看，无百分制、排名、善恶分 | 档案式、证据式结算，视觉成熟克制 |

# 五、变更管理

任何影响五册剧情顺序、角色动机、数学规则、任务结果或Boss状态的修改，必须先建立脚本变更单。

概念图可以探索外观，但不得反向覆盖已冻结的内容边界；发现矛盾时回到确认门处理。

S2阶段允许收敛资源数量、复用模块和降低美术成本，但不能删除关键可读状态和角色决定权。

本索引只确认内容基线，不代表正式资源验收，也不代表Unity工程启动。
