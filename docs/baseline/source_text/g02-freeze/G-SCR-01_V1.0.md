# 一、本册体验目标

| 目标 | 玩家体验 | 验收信号 |
| --- | --- | --- |
| 30秒内有效操作 | 玩家不是看完长动画才开始，而是在警报舱内立刻检查仪表或拉出七码 | 首次试玩者30秒内完成一次有效交互 |
| 建立星宇与七码关系 | 星宇偏行动，七码偏分析；两者都不能独立给出完整答案 | 玩家能说出二者分工，不把七码当自动提示器 |

| 第一次可恢复危险 | 用短距瞬移穿过垃圾雨与电弧，失败后快速回到舱门安全点 | 失败后15秒内重新控制，无长演出重复 |

# 三、逐场景制作脚本

## 3.1 S00-01｜倾斜的警报舱

| 字段 | 制作要求 |
| --- | --- |
| 进入条件 | 新游戏或读取“G02开场未完成”状态。 |
| 场景构图 | 固定广角：倾斜舱体、左侧警报仪表、中央电弧、右侧七码槽同屏。镜头不摇晃，只用局部震动和悬挂物表达坠落。 |
| 玩家目标 | 在30秒内完成第一个有效操作，并意识到“先看数据再行动”。 |
| 可交互 | 高度仪、外壳受损图、七码槽。三个交互任意一个可先做。 |
| 关键状态 | G02.Opening.FirstInteraction；G02.Opening.InstrumentReadCount。 |
| 失败/恢复 | 本段无失败；若20秒无操作，七码槽发出一次机械敲击，不显示答案箭头。 |

### 对白与声音

| 说话者/触发 | 文本 |
| --- | --- |
| 系统警报 | 外壳稳定度：18%。姿态修正失败。 |
| 星宇｜检查高度仪 | 下降得太快。不是正常着陆。 |
| 星宇｜检查外壳图 | 右侧破口还在扩大。 |
| 七码｜未被拉出前 | ……有人愿意先把我从墙里拿出来吗？ |

数学与认知设计：只呈现相对变化：高度持续下降、外壳稳定度从22%降到18%、右侧受损扩大。玩家不需要计算，但要先建立“读取量和趋势”的习惯。

UI与提示：左下只显示一个短提示：“检查舱内状态”。20秒未操作后改为“声音来自右侧槽位”。

## 3.2 S00-02｜把七码从墙里拔出来

| 字段 | 制作要求 |
| --- | --- |
| 进入条件 | 玩家首次点击七码槽。 |
| 场景构图 | 人物双近景；七码卡在减震槽中，三枚锁扣处于不同方向。 |
| 玩家目标 | 按外形方向依次释放三枚锁扣；理解七码提供分析而非代替操作。 |
| 主要交互 | 观察锁扣纹理→按正确方向拖动。错误不会扣血，只会弹回并产生幽默反馈。 |
| 关键状态 | Party.QiMaJoined=True；Scanner.BasicEnabled=True。 |
| 失败/恢复 | 无硬失败；连续3次错误后，锁扣边缘出现方向磨痕，仍不直接高亮正确按钮。 |

### 对白与声音

| 说话者/触发 | 文本 |
| --- | --- |
| 七码｜出槽 | 我建议先别死。这个建议免费。 |
| 星宇 | 那收费的建议呢？ |
| 七码 | 先看落点，再决定有没有机会收费。 |
| 星宇 | 扫描外面。找能撑住我们的地方。 |

数学与认知设计：用三种锁扣方向做低负担的空间方向热身；不作为知识考核。

UI与提示：首次显示“七码：分析/寻路”图标，但图标下标注“提供证据，不自动选择”。

## 3.3 S00-03｜三个蓝色落点

| 字段 | 制作要求 |
| --- | --- |
| 进入条件 | 七码加入，玩家点击外部扫描仪。 |
| 场景构图 | 舷窗外三处落点A/B/C以环境蓝光区别；扫描面板覆盖不超过画面35%，仍可看到外部垃圾流。 |
| 玩家目标 | 比较距离、垃圾密度、侧向冲击和遮蔽，选择综合风险最低的落点。 |
| 主要交互 | 点击A/B/C→切换“距离/撞击/遮蔽”三层→确认落点。 |
| 关键状态 | G02.Landing.SelectedZone=A/B/C；G02.Math.M01.ExplanationTags。 |
| 失败/恢复 | 选择B或C不立即判错：进入更困难的入场路径；连续失败后可回到扫描选择。A为推荐基础路线。 |

### 对白与声音

| 说话者/触发 | 文本 |
| --- | --- |
| 七码 | 最近的不一定最安全。中间那片废料正在一起下坠。 |
| 星宇｜查看A | 远一点，但后面有屏幕墙。 |
| 星宇｜查看B | 路最短。撞击面也最大。 |
| 星宇｜查看C | 垃圾少，侧风把碎片往那边推。 |
| 七码｜确认前 | 选你能解释的，不要选看起来最亮的。 |

数学与认知设计：基础路线不显示总分。A：距离中、撞击中、遮蔽高；B：距离近、撞击高、遮蔽低；C：距离远、撞击低、侧向风险高。辅助模式可显示“综合风险条”，挑战模式只给原始仪表。

UI与提示：确认按钮文案：“按这个落点修正”。确认后允许用一句标签说明理由：遮蔽更好/撞击更低/距离更短；不要求书写。

## 3.4 S00-04｜裂口与三个瞬移锚点

| 字段 | 制作要求 |
| --- | --- |
| 进入条件 | 落点确认；飞船姿态修正导致外壳裂口扩大。 |
| 场景构图 | 固定侧视：起点、安全梁、舱门前平台三个锚点均在同一镜头。 |
| 玩家目标 | 完成两次短距瞬移，理解“只能到预设锚点、不能穿过危险实体”。 |
| 主要交互 | 选择锚点→确认瞬移；第二次需要等待电弧间隙。 |
| 关键状态 | Skill.Blink.BasicTutorialComplete=True。 |
| 失败/恢复 | 误入电弧只退回上一个锚点；0.9秒恢复镜头，连续失败缩至0.5秒。 |

### 对白与声音

| 说话者/触发 | 文本 |
| --- | --- |
| 七码 | 左边梁架还有固定点。你的瞬移能抓住它。 |
| 星宇 | 我知道。 |
| 七码 | 你上次说这句话以后，我们换了半艘船。 |
| 星宇｜成功 | 这次只换一扇门。 |

数学与认知设计：玩家通过电弧周期观察“安全窗口”，但不显示倒计时数字。辅助模式增加节拍光；挑战模式仅保留声音与亮度变化。

UI与提示：锚点使用形状和纹理区分可用/冷却/被遮挡状态，避免只靠颜色。

## 3.5 S00-05｜垃圾雨中的舱门

| 字段 | 制作要求 |
| --- | --- |
| 进入条件 | 到达舱门前平台。 |
| 场景构图 | 舱门外为固定广角；三条落物轨迹、一次尾索横扫、两个安全锚点清晰可见。 |
| 玩家目标 | 观察预警，分两段穿过垃圾雨；在中段回身拉七码越过破口。 |
| 主要交互 | 短移动、瞬移、拉取七码；不能在预警后打开长文本。 |
| 关键状态 | HZ-01.Completed；Checkpoint.G02-L00-Exit。 |
| 失败/恢复 | 被坠物或尾索击中→0.8秒现场后果→回舱门安全点；不播放完整出舱演出。 |

### 对白与声音

| 说话者/触发 | 文本 |
| --- | --- |
| 星宇｜第一次预警 | 看到落点了。 |
| 七码 | 我看到的是一整片正在落下来的“落点”。 |
| 星宇｜拉七码 | 别分析了，过来。 |
| 七码｜安全后 | 记录：星宇第一次在听完分析前采取了正确行动。 |

数学与认知设计：路线判断强调顺序和时间：先穿过短空档，再等待尾索横扫，最后移动到遮蔽。辅助模式允许延长预警；不改变剧情评价。

UI与提示：危险前使用影子、金属啸叫和地面纹理三重预警。失败不显示“你应该先去哪里”。

### 对白与声音

| 说话者/触发 | 文本 |
| --- | --- |
| 七码 | 结论：我们还活着。飞船对此持保留意见。 |

UI与提示：首次出现区域目标：“找到能避开垃圾雨的地方”。不使用自动导航箭头，只在区域图标出已观察方向。
