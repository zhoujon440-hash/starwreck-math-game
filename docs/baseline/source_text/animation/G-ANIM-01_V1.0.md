图片解密游戏轻动效与骨骼动画方案

分层2D、轻微抖动、局部循环与可选简易骨骼

| 文件编号 | G-ANIM-01 | 版本 | V1.0 |
| --- | --- | --- | --- |
| 阶段 | S2概念设计修订 | 工程状态 | Unity未启动 |

| 结论：首版不需要完整骨骼动画。图片解密的核心是线索可读、状态变化和局部反馈；全量骨骼会增加切图、权重、动作、适配和调试成本，收益不足。 |
| --- |

# 一、推荐技术路线

| 层级 | 实现方式 | 典型内容 |
| --- | --- | --- |
| 场景基础 | 分层Sprite＋轻微视差 | 远景、背景、主体、前景遮挡 |
| 画面“活感” | Transform微位移/旋转/缩放＋低频噪声 | 布条、吊线、旧屏幕、漂浮灰尘 |
| 局部循环 | 2—6帧序列、Sprite切换、材质参数 | 眼睛眨动、屏幕闪烁、能源脉冲、烟气 |
| 角色反馈 | 关键姿态替换＋局部子图层旋转 | 点头、抬手、扫描眼、腰带动作 |
| 谜题反馈 | 状态图替换＋遮罩/高亮＋音效 | 线路接通、归属标记、塔状态、Boss权限 |
| 镜头 | 固定构图＋极轻微环境抖动 | 危险来临、机械启动、坠落余震 |

# 二、骨骼动画是否需要

| 对象 | 首版结论 | 原因 |
| --- | --- | --- |
| 星宇 | 默认不使用完整骨骼；仅在重复全身动作确有必要时采用5—8骨简易2D骨骼 | 关键姿态和局部图层足以满足图片解密 |
| 七码 | 不需要；屏幕表情＋天线/机械臂局部旋转 | 机械结构适合独立图层 |
| 豆包 | 不需要；状态贴图、呼吸、灯光与姿态切换 | 避免把角色做成可支配电池道具 |
| 阿铆 | 不需要；半身/全身姿态切换 | 主要承担对话和工坊互动 |
| 狰与五尾 | 不使用角色骨骼；五尾用分段父子层级或程序曲线 | 机械尾索更适合节点链与程序摆动 |
| 居民 | 不需要；基础体＋头部/配件/表情变体 | 最大化复用 |

# 三、轻微抖动参数边界

| 对象 | 建议范围 | 注意事项 |
| --- | --- | --- |
| 环境整体 | 0.2—0.8像素等效位移；0.05°—0.2°旋转；周期1.5—4秒 | 不能持续高频抖动，避免眩晕 |
| 角色待机 | 1—2像素呼吸；局部延迟2—4帧 | 头部/眼睛优先，身体幅度小 |
| 危险冲击 | 2—6像素、0.1—0.25秒衰减 | 数字、文字、UI和关键线索不参与 |
| 定格质感 | 动作以8—12fps采样显示 | Unity仍可60fps运行，仅视觉采样低帧 |
| 视差 | 远景0.1、中景0.3、前景0.6的相对系数 | 鼠标移动或镜头微移驱动 |

# 四、首版实施优先级

| 优先级 | 内容 | 是否必须 |
| --- | --- | --- |
| P0 | 场景分层、可点击热区、状态替换、UI反馈 | 必须 |
| P0 | 旧屏幕闪烁、能源脉冲、危险预警、角色眼部反馈 | 必须 |
| P1 | 环境视差、布条/线缆摆动、烟尘循环 | 推荐 |
| P1 | 星宇3—5个短动作序列 | 推荐 |
| P2 | 简易2D骨骼试验 | 仅灰盒验证后确认 |
| 不做 | 全3D角色、全套走跑跳、复杂布料和面部骨骼 | 首版排除 |

# 五、S3与Unity实施建议

优先使用Unity原生SpriteRenderer、Animator、Animation Clip、Timeline和2D Animation包，避免首版采购插件。

图片按“SceneID_Layer_Function_State”命名，角色按“Character_Pose_Expression_Equipment”命名。

每个场景先做一张低分辨率分层样板验证热区与轻动效，再批量出正式图。

是否使用简易骨骼，延后到M0灰盒：只有当姿态切换明显僵硬且同一动作高频复用时才启用。

# 六、最终方案

| 正式基线：分层2D图片解密＋定格感轻动效＋局部序列帧；完整骨骼动画不是首版必需项，简易2D骨骼仅作为可选优化。 |
