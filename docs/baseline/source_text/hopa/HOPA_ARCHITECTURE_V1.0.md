# 二、核心玩法结构

## 2.1 高清全景探索与互动寻物

场景首先是一张可长时间观察的高清艺术全景图，必须包含叙事环境、可疑细节、隐藏物品和视觉引导。

寻物模式至少包含：文字列表寻物、轮廓寻物、组合寻物、找不同、碎片复原和环境线索发现。

找到物品后进入背包；物品不是简单计数资源，而是后续场景或小游戏的操作凭证。

可互动区域可使用克制的闪光、呼吸高亮或提示圈，但正常探索时不得持续全屏提示。

## 2.2 背包、组合与拖拽使用

| 阶段 | 玩家操作 | 系统反馈 |
| --- | --- | --- |
| 发现 | 点击或完成寻物获得物品 | 物品飞入背包，记录来源与用途线索 |
| 检查 | 旋转/放大物品，阅读标记 | 发现缺口、密码、可拆部件或组合关系 |
| 组合 | 把两个或多个物品拖入组合槽 | 生成可用工具，保留组合过程说明 |
| 使用 | 从背包拖到场景热点 | 出现吸附反馈与局部交互动画 |
| 结果 | 开启小游戏、隐藏区域或剧情 | 场景切换到新状态，物品消耗或保留 |

## 2.3 迷你益智游戏

拼图类：碎片复原、华容道、图案拼合、画作与信件修复。

机械类：齿轮传动、电路连接、管线旋转、压力平衡、密码盘与符号组合。

观察类：找不同、顺序记忆、线索连线、双图对照与隐藏规律。

数学类：分数调配、面积与周长、坐标路线、几何拼合、周期时间、数据与概率。

每个小游戏必须有说明、重置、提示、跳过、成功反馈、错误反馈和完成后的场景变化。

# 四、场景分层、热点与状态管理

图2：2D场景分层与热点架构

## 4.1 场景状态

| 状态 | 用途 |
| --- | --- |
| 初始状态 | 第一次进入时的环境、可见物品和角色位置 |
| 调查状态 | 已点击热点、已阅读文本、已拾取物品的变化 |
| 解谜中状态 | 机关开启、小游戏进行、临时装置运行 |
| 完成/修复状态 | 门打开、供电恢复、危险解除、角色位置改变 |
| 剧情后状态 | 章节推进后新增或移除热点，替换环境叙事 |

## 4.2 数据化原则

每个场景用SceneID管理；每个热点用HotspotID管理；每个物品用ItemID管理。

热点条件由剧情变量、背包物品、小游戏状态和角色能力共同决定。

视觉替换和交互逻辑分离：场景状态决定显示层，事件系统决定点击结果。

同一小游戏模板通过数据表更换图形、数值、难度和叙事包装，减少独立开发工作量。

# 五、提示、跳过与流畅体验

| 功能 | 正式规则 |
| --- | --- |
| 提示能量 | 随时间恢复，也可通过探索和阅读档案补充 |
| 一级提示 | 提示应调查的场景或功能区域 |
| 二级提示 | 缩小范围并高亮可疑区域 |
| 三级提示 | 指出目标物、可用背包物或下一步机关 |
| 小游戏跳过 | 等待能量或一定时间后可跳过；展示结论和场景结果 |
| 辅助记录 | 记录为“使用辅助完成”，不扣分、不排名、不阻断剧情 |

# 六、角色能力的HOPA化解释

| 能力 | 正确定位 | 典型用法 | 禁止方向 |
| --- | --- | --- | --- |
| 星宇·瞬移 | 场景切换/双锚点机关权限 | 已发现锚点间移动，改变观察角度或同步机关 | 战斗闪避、穿越未探索区域 |
| 星宇·缩小 | 进入微缩隐藏场景 | 设备内部、模型世界、狭缝寻物 | 自由缩放、跳过机关 |
| 星宇·复制体 | 双点同步操作 | 同时压住两个开关、镜像小游戏 | 战斗分身、自动解题 |
| 七码·搜寻 | 提示扫描 | 短暂标记可疑区域或隐藏层 | 直接显示全部答案 |
| 七码·分析 | 证据关系工具 | 连接线索、发现矛盾与缺项 | 自动给出最终结论 |
| 七码·寻路 | 地图与任务辅助 | 提示出口、场景顺序和可达路径 | 实时导航战斗移动 |
