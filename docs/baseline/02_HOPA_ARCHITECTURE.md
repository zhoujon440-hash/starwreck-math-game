# HOPA游戏架构冻结基线

## 1. 产品形态

《星骸拾荒者：十二星门》是以高清图像探索、场景找物、背包道具、局部机关、迷你游戏和剧情推进为核心的HOPA游戏。

当前技术路线：Vite + TypeScript + HTML5/PWA。

Unity资料仅作为结构化数据参考，不是当前运行时引擎。

## 2. 核心运行模块

- `SceneManager`：场景切换、进入/离开、场景状态；
- `HotspotManager`：不可见热点、条件、范围和语义；
- `HiddenObjectManager`：HOS目标、干扰物、拾取与消失；
- `InventoryManager`：背包、关键道具、组合和状态；
- `ItemUseSystem`：选择后点击、鼠标拖拽、触屏拖拽；
- `ZoomSceneManager`：局部放大、容器、设备内部和微缩场景；
- `MiniGameManager`：拼图、线路、航线、排序、测量等；
- `DialogueManager`：数据驱动对白、角色状态、历史和跳过；
- `ObjectiveManager`：任务目标、前置条件和完成反馈；
- `HintManager`：方向→区域→短暂扫描三级提示；
- `SaveManager`：自动存档、安全节点、迁移和损坏回退；
- `AudioManager`：环境、交互、对白提示和状态音效；
- `ContentLoader`：G01—G13数据加载、校验和版本迁移。

## 3. 场景状态

所有正式场景统一使用S0—S6。状态含义由场景数据定义，但必须满足：

- 状态变化具有可见画面反馈；
- 物件、热点、对话、目标和音效可按状态启停；
- 读档后恢复到一致状态；
- 状态ID不得在正式玩家UI泄露。

## 4. 数据契约

每个场景至少包含：

- sceneId、chapterId、title、artboard；
- states；
- hotspots；
- hiddenObjectSets；
- items；
- itemUses；
- dialogues；
- objectives；
- hints；
- checkpoints；
- variables；
- assetMappings；
- nextSceneId。

正式内容必须数据驱动，不得把章节对白、角色状态或道具链硬编码在视图组件中。

## 5. HOPA交互规则

- 热点默认不可见；鼠标悬停不得显示大圆点或常驻框。
- 三级提示可短暂扫描，但不自动点击或直接给出答案。
- 找物目标必须嵌入图像环境，不得用按钮网格代替。
- 找到物品后，独立图层或修补层必须体现物件消失。
- 关键道具错误使用不消耗。
- 危险失败仅撤销当前步骤或返回安全节点。
- 画面、热点和物件使用统一设计坐标系。

## 6. 能力边界

- 星宇·瞬移：仅在已发现、修复、授权的锚点间切换；
- 星宇·缩小：仅进入指定微缩场景；
- 星宇·复制体：仅用于双点同步和镜像机关；
- 七码·搜寻：缩小搜索范围，不指出答案；
- 七码·分析：只分析已收集证据；
- 七码·寻路：只显示已探索和已开放节点。

## 7. 存档规则

存档至少记录：

- schemaVersion；
- chapter/scene/state；
- 已找物品；
- 背包；
- 已使用道具；
- 对话进度；
- 目标进度；
- 谜题进度；
- 角色状态；
- 检查点；
- 全局变量。

G01载入任何旧存档后必须强制`world_star_core_count=0`。

## 8. 明确禁止

战斗、攻击、血条、伤害、敌人AI、RPG技能树、自由移动、实时3D、大规模骨骼动画、手速型Boss、按钮答题页、可见圆点热点和纯色占位图均不属于当前产品。
