# 开发说明

## 1. 技术边界

本项目是浏览器端固定镜头 HOPA。技术实现围绕“观察场景 → 收集道具 → 拖拽使用 → 局部解谜 → 状态切换”展开。

明确不在当前架构中引入：

- 角色自由移动与导航网格。
- 3D 渲染场景。
- 战斗数值、回合制或平台跳跃控制器。
- 用按钮列表替代场景探索。
- 在正式场景中常驻显示圆点热点。

## 2. 运行时分层

### 内容层

`src/content/g01.ts` 是当前章节配置，包含：

- S0–S6 状态文案。
- 道具定义与背包裁切位置。
- 热点百分比矩形。
- 热点生效状态。
- 事件驱动的状态转换。

后续章节应新增独立内容文件，避免把剧情常量写进 UI。

### 规则层

`src/game/engine.ts` 负责：

- 验证当前状态下允许的动作。
- 查找物品并写入背包。
- 匹配道具与场景目标。
- 完成迷你游戏。
- 触发场景状态转换。
- 自动保存与安全节点保存。
- 提供提示候选。

状态转换统一使用事件字符串：

```text
start
found:all
use:<item-id>:<target-id>
puzzle:<puzzle-id>
inspect:<hotspot-id>
```

同一个动作必须先在当前状态找到有效热点，再允许修改存档。

### 交互层

`src/ui/GameView.ts` 渲染固定镜头场景、背包、提示和局部放大窗口。

`src/game/drag.ts` 使用事件委托同时支持：

- 桌面 HTML5 drag-and-drop。
- 触屏 Pointer Events 拖拽。
- 点选道具后点击目标的可访问替代操作。

### 迷你游戏层

迷你游戏遵循 `MiniGameController<Input>`：

```ts
interface MiniGameController<Input> {
  get snapshot(): MiniGameSnapshot
  start(): void
  act(input: Input): MiniGameSnapshot
  reset(): void
}
```

迷你游戏只负责自身规则。完成后由 UI 调用 `engine.completePuzzle(puzzleId)` 推进章节状态。

### 存档层

`LocalSaveRepository` 保存当前进度和最近安全节点。存档结构带有 `version: 1`；更改字段时必须新增迁移或提升版本，不能静默破坏旧存档。

## 3. S0–S6 状态图

| 状态 | 核心动作 | 完成条件 | 安全节点 |
| --- | --- | --- | --- |
| S0 | 剧情引入 | 接管应急权限 | 是 |
| S1 | 场景找物 | 找齐三件道具 | 否 |
| S2 | 道具使用 | 扳手打开检修舱 | 是 |
| S3 | 局部放大 / 电路谜题 | 完成或跳过电路 | 否 |
| S4 | 道具使用 | 记忆棱晶写入控制台 | 是 |
| S5 | 道具使用 | 星位罗盘校准领航盘 | 否 |
| S6 | 场景完成 | 进入下一场景的挂接点 | 是 |

## 4. 视觉与热点规范

- 场景基底必须是正式插画或经过批准的高质量场景资产。
- 热点使用与画面比例无关的百分比矩形。
- 未触发提示时热点完全融入场景。
- 悬停和键盘聚焦只允许低强度材质边缘反馈。
- 提示反馈应短暂、局部、非圆点化。
- 迷你游戏内部的节点、按钮和电路元件不属于正式场景热点，可按谜题可读性呈现。
- 道具收集后，后续资产版本应提供状态图层或局部修补图，彻底移除背景中的已拾取物。

## 5. 添加新场景

1. 从冻结脚本提取场景目标与状态序列。
2. 为场景建立正式背景和必要的状态图层。
3. 在内容层定义道具、热点和状态转换。
4. 把新谜题实现为独立 `MiniGameController`。
5. 标注安全节点和失败回退逻辑。
6. 添加规则测试。
7. 在桌面鼠标、键盘、触屏横屏三种输入方式下验收。

## 6. 测试要求

每次提交至少运行：

```bash
npm test
npm run build
```

新增状态规则时必须覆盖：

- 非法状态不能提前取物或使用道具。
- 找齐物品后只转换一次。
- 道具消耗与背包状态一致。
- 安全节点保留正确背包内容。
- 谜题失败与回退不会生成重复道具。

## 7. 当前已知限制

- 第一场景只有单张背景，拾取后的物体仍存在于底图中，但已失去交互；下一资产轮次应补状态修补层。
- 音频、字幕时序、完整剧情脚本和人物演出尚未导入。
- PWA 以本地存档为主，尚无跨设备同步。
- 尚未接入内容编辑器，热点坐标仍由 TypeScript 配置维护。
- 当前仓库没有项目方所述的既有冻结资料；导入后需做一次内容差异审查。
