# SCN-G01-00《拾光号熄灯》实现说明

## 交付边界

本轮只实现 G01 第一场景，不提前制作 G01 其余七个场景或 G02。

主角固定为星宇；搭档称为七码；`world_star_core_count` 固定为 0。G01 是独立序章，不产生十二主星核。

## 可玩链路

```text
S0 断电红光
  找到应急手灯
        ↓
S1 手灯照亮熔断配电盒
  关键手灯不消耗
        ↓
S2 维修柜开启
  局部特写内找出临时保险丝、旧扳手、绝缘手套、线号标签
        ↓
S3 临时保险丝进入背包
  选中或拖拽到应急照明槽
        ↓
S4 短路保护解除
  合上保护开关
        ↓
S5 应急照明恢复（安全节点）
  确认进入下一场景入口
        ↓
S6 场景交接就绪
```

S6 只是后续场景挂接点，不包含“找回七码”的实际场景内容。

## 视觉分层

运行时使用下列层级：

1. `scene-canvas`：固定 `1672 × 941` 设计空间，按 contain 规则统一缩放和留黑。
2. `scene-art`：不含可拾取物的正式手绘拾光号领航舱底图。
3. `collectible-object`：由 `foundItemIds` 控制显隐的独立透明物件图层。
4. `distribution-box-layer`：S1 手灯调查时的局部光束。
5. `scene-art` 状态图：S0/S1 使用真实绘制的关闭柜门整图，S2 后切换为真实打开柜门整图。
6. `lighting-layer`：S4 预亮、S5/S6 完整照明恢复。
7. `scene-treatment`：断电红光、暗角和场景状态色调。
8. `foreground-layer`：前景暗部与 HUD 分隔。
9. `pickable-layer`：与底图共用设计空间的默认透明语义热点。

热点只有在键盘聚焦、轻微悬停或三级提示时短暂显示材质边缘反馈；正式画面没有圆点、文字标签或常驻调试框。

维修柜使用不含目标物、但包含电缆、工具卷、网兜、零件盘与抽屉杂物的正式手绘特写 `public/assets/g01-maintenance-cabinet-v2.png`。手灯、保险丝、扳手、手套和线号标签分别使用独立透明 PNG；拾取后节点从 DOM 移除，读档时按 `foundItemIds` 恢复。维修柜内的实际底图复制前景对三件目标形成持续遮挡，不使用圆点、描边、箭头或文字标记。右侧文字只作为 HOS 目标清单，不是可点击按钮。

正式 UI 的 `DEBUG_UI` 默认关闭；只有开发环境显式使用 `?debug=1` 才显示状态编号、schema 和稳定 ID。CI 正式截图不启用该参数。

### 坐标校准

维修柜底图、独立物件和热点同样使用 `1672 × 941` 坐标系，并以 `aspect-ratio` 保持比例。

## 数据与状态

章节配置位于 `src/content/g01.ts`，稳定 ID 沿用冻结基线：

- `HS-G01-0001` 应急手灯
- `HS-G01-0002` 熔断配电盒
- `HS-G01-0003` 维修柜
- `HOS-G01-001-*` 维修柜找物
- `HS-G01-0004` 应急照明槽
- `HS-G01-0005` 保护开关
- `HS-G01-0006` 下一场景入口

状态引擎位于 `src/game/engine.ts`。内容层通过事件驱动状态转换：

```text
found:all
use:<item-id>:<target-id>
inspect:<hotspot-id>
puzzle:<puzzle-id>
```

非法状态动作不会修改存档。道具只有在目标匹配后才按 `consumeItem` 规则消耗。

## 背包与输入

- 桌面：HTML5 drag-and-drop。
- 触屏：Pointer Events 拖拽。
- 键盘与替代操作：点选背包道具，再点击场景目标。
- 错误使用临时保险丝不会消耗。
- 旧扳手、绝缘手套、线号标签计入 HOS 完成，但不进入长期背包。

## 提示系统

同一目标的提示按三级递进：

1. 只给左右方向；
2. 缩小到上下区域；
3. 短暂扫描具体物件区域。

维修柜打开时，提示范围自动切换到局部特写，不会在主场景错误高亮。

## 存档

`LocalSaveRepository` 使用 `localStorage`：

- `starwreck:save:G01:v1`
- `starwreck:checkpoint:G01:v1`

存档包含 `schemaVersion: 1`，并能迁移早期开发版的 `version: 1` 字段。

场景视觉状态完全由 `sceneState`、`foundItemIds`、`inventoryItemIds` 和 `usedItemIds` 派生，因此重载后维修柜、保险丝、照明和背包保持一致。

安全节点：

- S0：场景初始。
- S3：已完成维修柜找物，保险丝在背包。
- S5：应急照明恢复。
- S6：下一场景交接。

## PWA

- Vite + TypeScript 严格模式。
- `vite-plugin-pwa` 生成 Service Worker。
- 场景、维修柜、图标、JS、CSS 和 HTML 全部本地缓存，不依赖远程 CDN。
- manifest 固定横屏、全屏显示、中文语言和 192/512 图标。

## 测试与截图

Vitest 覆盖：

- 背包与道具消耗。
- S0—S6 冻结链路。
- 临时保险丝错误使用不消耗。
- 安全节点回退。
- `schemaVersion` 序列化与读档恢复。
- G01 星核数保持 0，包括旧存档注入非零值后的强制归零。
- 迷你游戏控制器顺序校验。

Playwright 在两个视口执行四项浏览器验收，并收集浏览器控制台错误：

- 按真实热点中心坐标点击并验证固定画布比例。
- 拾取前物件图层可见，拾取后节点消失。
- S3 重载后保险丝仍在背包、维修柜目标物仍保持消失。
- S5 重载后照明状态保持恢复。
- 真实 HTML5 桌面拖拽：错误目标不消耗保险丝，正确目标进入 S4。
- 正式页面不出现状态编号、schema、项目验收或交付开发文字。
- S0/S1 关闭柜门与 S2 打开柜门分别使用不同正式整图。
- 背包、目标卡和进度区与手灯、配电盒、维修柜、照明槽和保护开关不相交。
- 仅在验收截图中叠加配电盒、照明槽和保护开关热点边界。

CI 将两种分辨率下的 S0、S1、S2 打开主场景、S2 拾取前、S2 保险丝拾取后、S3、S3 重载、S5、正式无开发文案界面和 debug 热点校准图上传为 `g01-visual-acceptance-*` artifact。

## 已知限制

- 场景背景中的非交互科幻小物属于装饰，不计入 HOS。
- 当前使用 `localStorage`，尚未实现跨设备同步。
- 迷你游戏框架已建立，但冻结的 SCN-G01-00 不包含独立迷你游戏；首个实际谜题应在项目负责人批准的后续场景中接入。
