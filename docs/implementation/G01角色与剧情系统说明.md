# G01角色与剧情系统说明

## 本轮范围

本实现连续开放 `SCN-G01-00《拾光号熄灯》` 与 `SCN-G01-01《找回七码》`。其余六个
G01 场景只注册剧情数据，`playable` 为 `false`，不会在正式界面中提供入口。

## 数据边界

- `src/content/characters/`：角色资料、可用表情、运行时图片和档案字段。
- `src/content/dialogues/`：对白、触发序列、条件、角色状态与剧情效果。
- `src/content/story/g01-scenes.ts`：G01 八场剧情节点和场景间条件。
- `src/content/g01-adventure.ts`：把场景、角色、对白和剧情节点组合为单一冒险定义。
- `src/game/engine.ts`：只解释内容数据，负责状态转换、对白推进、档案解锁与持久化。
- `src/ui/GameView.ts`：渲染当前数据，不保存剧情文案，也不按状态硬编码对白。

## 对话演出

对话支持左右稳定站位、当前说话者突出、表情切换、逐字显示、点击/回车/空格继续、可关闭的
自动播放、历史记录和可跳过序列。`requiredFirstPlay` 的关键序列不可整段跳过；普通短反应可
略过，略过时仍按顺序执行必要效果并写入历史。

角色首次解锁后出现一次介绍卡。介绍卡确认状态写入存档，重载后不会重复弹出。七码恢复前档案
保持锁定；恢复并确认介绍后才开放完整资料。

## 两场连续流程

《拾光号熄灯》保留原有手灯、配电盒、维修柜找物、保险丝拖拽和照明恢复链，并在开场和关键
步骤插入数据对白。照明恢复后写入 `g01_scene_00_story_complete`，自然开放导航核心舱。

《找回七码》先以独立场景图层显示关机的七码。玩家调查机体、打开核心特写、找出四件部件，
再按清理接口、安装芯片、接回线路、恢复保护的顺序拖拽。线路校准完成后，七码从启动状态恢复，
解锁角色介绍并进入第一段完整搭档对白。

## 存档 v2

本地存档记录当前场景和各场景状态、当前对白、已读/跳过对白、历史、已解锁/已介绍角色、角色
当前表情、HOPA 已发现物品、背包、已使用道具、谜题完成和中途路径。v1 存档会迁移到 v2；
无论迁移还是新存档，G01 的 `world_star_core_count` 都会强制归零。

## 视觉与交互约束

场景继续使用统一 `1672 × 941` 坐标。正式热点透明且无圆点、文字或描边；仅 CI 的 debug
校准截图会临时注入热点框。对话期间 HOPA 层不可操作，对话结束立即恢复。角色图片、可拾取
部件和已安装部件均为独立透明图层，拾取、使用与重载后的显示由存档状态决定。

## 验证

- Vitest：内容校验、档案解锁、对白顺序、条件、表情、恢复变量、v1/v2 存档和星核归零。
- Playwright：两场连续通关、正式角色图、找物消失、错误拖拽不消耗、线路校准、角色介绍、
  关键对白、历史、重载、双分辨率视口和控制台零错误。
- CI artifact：`g01-character-story-acceptance-<run_number>`。
