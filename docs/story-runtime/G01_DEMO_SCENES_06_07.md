# G01 Demo：SCN-G01-06—07 运行时说明

## 范围与来源

PR-C 完成 `SCN-G01-06《锈环星求救信号》`、`SCN-G01-07《坠落之前》`
以及 G01 到 G02 的只读交接。正式剧情、对白、热点、变量和存档来源于
`PKG-G01-V3.0` 与 `data/source/g01/json/**`。没有开发 G02 玩法、Issue #10
或后续星球。

正式源未提供 SCN06 独立 HOS 编号，因此信号接收器找物、局部机关与危险分支使用
`RUNTIME-*` 适配 ID，并在 `data/source/g01/pr-c/runtime-contract.json` 中绑定
正式父 ID；没有伪装成官方编号。

## SCN-G01-06 完整操作

1. 调查正式热点 `HS-G01-0025`，打开求救信号接收器。
2. 在 `RUNTIME-HOS-G01-06-SIGNAL-TRACE` 中找到信号棱镜、调谐线圈、
   `ITM-G01-013` 求救记录和相位钥；空记录壳、烧毁线圈和弯曲相位针保留。
3. 目标物拾取后从独立图层消失；求救记录进入背包和证据记录，校准组件直接进入机关。
4. 打开 `RUNTIME-PUZ-G01-SIGNAL-ALIGNMENT`，依次锁定频段、同步相位、提升增益。
5. 复原并播放 DLG-G01-0017—0018，确认信号来自锈环星旧屏幕谷方向。
6. 按正式顺序操作 `HS-G01-0026`、`HS-G01-0027`、`HS-G01-0028`，依次授权
   七码搜寻、分析和已探索节点寻路。
7. 合上运行时存档拨杆，进入 S6 并前往近地轨道。

瞬移、缩小和复制体不会在该场景或 Demo 结束时解锁。

## SCN-G01-07 完整操作

1. 进入近地轨道并播放 DLG-G01-0020。
2. 调查 `HS-G01-0029`，在落点扫描近景中依次执行搜寻、分析、寻路。
3. 扫描完成后播放 DLG-G01-0021，确认舷窗中央安全走廊。
4. 打开冲击缓冲机关，依次稳定船体姿态、接通缓冲、闭合着陆锁。
5. 点击 `HS-G01-0030` 保存着陆前状态，播放 DLG-G01-0022—0024。
6. 点击 `HS-G01-0031` 打开舱门，进入 S6。
7. 由完成面板执行一次显式 G01 交接，进入 `G02-BOUNDARY`。

## 危险软失败

正式危险 `DANGER-G01-004` 通过可见的
`RUNTIME-HS-G01-07-UNSAFE-CORRIDOR` 实现。S1、S2、S3、S4 任一阶段选择不稳定
走廊，都会保存失败前有效状态并进入
`SCN-G01-07:orbit-safe-node`。刷新仍停在安全节点；继续后恢复原阶段。

软失败保留关键物、HOS、拼图、证据、对话历史和已经确认的正确步骤，不创建新证据、
不重复发放物品，也不重置整个场景。

## 存档、提示与结束变量

两场都具有 S0—S6。S0、S2、S5、S6 是持久 checkpoint；S1、S3、S4 是正常自动
存档的临时状态。三级提示每次第三次调用都会通过引擎执行当前唯一合法步骤。

G01 完成变量只在 `SCN-G01-07` 已到 S6、落点证据存在且三项基础能力完成授权后，
由“完成 G01 序章”动作写入。结束状态为：

- `g01_chapter_complete=true`
- `g01_handoff_to_g02=true`
- `world_star_core_count=0`

`G02-BOUNDARY` 的物品、热点、HOS、拼图、对白流程均为 0。

HOS 物件使用独立 RGBA 图层；近景和状态变化为独立位图。完整来源、生成记录、加工方式
和 SHA-256 见：

- `data/source/g01/pr-c/runtime-art-manifest.json`
- `docs/art/G01_PR_C_RUNTIME_ASSET_PROVENANCE.json`
- `docs/art/G01_PR_C_RUNTIME_ASSET_SHA256.txt`

没有使用 PR #5 美术、第三方网络素材、纯色 SVG、Emoji、网页图标或未登记生成素材，
也没有修改星宇或七码的设计。
