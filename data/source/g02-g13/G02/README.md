《星骸拾荒者》G02锈环星
Unity数据级制作脚本 V2.1

主角：星宇｜HOPA实施样板｜程序、美术、关卡、测试共用

# 一、文档定位

本文件不是重写剧情母本，而是把G02 V2.0 HOPA实施脚本进一步转化为可供Unity开发使用的数据级制作规格。剧情、角色、场景、道具、MECH、DANGER和UI冻结内容不重新设计；新增内容主要是ID、条件、状态、数据字段和防卡死规则。

主角名称统一为“星宇”，所有旧名“小砾”均视为无效。

# 三、G02开发流程

1. SceneController读取“场景流程”，根据场景ID加载底图、热点、角色和当前S0—S6状态。

2. HotspotService读取“热点清单”，判断前置条件、接收点击/拖拽/扫描操作，并写入目标与证据状态。

3. InventoryService读取“背包道具流转”，错误使用只返回提示，不允许误消耗关键物。

4. PuzzleService根据资产映射打开UI-013—015，并调用MECH-001—003对应数据。

5. DangerService根据DANGER-001—006控制预警、时间窗口、安全节点和软重置。

6. DialogueService按对话ID和触发条件播放文本，并将关键对话写入回顾日志。

7. HintService按失败次数升级三级提示；Skip仅作用于独立小游戏，不跳过关键伦理选择。

8. SaveService在关键道具、场景修复、管理员权限和章节结束后自动存档。

# 四、场景状态模型

每个主场景采用统一状态：S0初始、S1已调查、S2关键道具取得、S3机关处理中、S4危险解除、S5场景修复、S6章节完成回访。

场景重载必须从最近持久状态恢复；S3一般为临时状态，退出小游戏时回到S2或最近安全节点。

# 五、管理员权限解除规则

不设置血条、攻击、伤害或敌人锁定。

五项管理员权限分别由资源登记、追踪转移、居民授权、五塔供能和清算扣维修解除。

失败不清空已解除权限；只重置当前子阶段。

豆包备用电达到安全线时自动断开，玩家无权强制继续。

供暖核心温度过低时必须归还；系统切换到备用连接方案。

十二秒稳定使用星门外环逐格点亮，同时提供数字辅助模式。

# 六、防卡死验收

| 风险 | 处理规则 |
| --- | --- |
| 关键道具误用 | 错误目标不消耗，自动返回背包 |
| 玩家提前离开小游戏 | 保存已确认步骤，恢复到S2或当前子阶段 |
| 豆包电量过低 | 自动断开并回退当前供能步骤 |
| 供暖温度过低 | 强制归还核心，保留其他连接 |
| 五塔过载 | 触发保护断电，只撤销最近一条连接 |
| 找物漏项 | 三级提示可定位；关键物不会被UI遮挡 |
| 场景回访 | 已安装物保留，已取物不重复刷新 |
| 旧名污染 | 数据校验禁止speaker/player_name写入“小砾” |

# 七、开发验收门

G02所有41个热点可通过数据表加载，不在场景脚本中硬编码。

5个找物场景均能记录完成状态，重进不刷新关键物。

18个背包道具不存在重复取得、错误消耗或流程断裂。

MECH-001—003、DANGER-001—006、UI-013—015、060—061调用正确。

管理员权限解除无战斗逻辑，五项权限均可独立软重置。

自动存档可恢复到最近安全状态，章节完成后正确解锁G03。

主工作簿包含10张数据表和1张统计页；CSV用于策划和程序批量导入；JSON用于Unity ScriptableObject或自定义数据管线转换。

本包是G02第一章实施样板。确认字段和粒度后，G03—G13必须复用数据结构，但不复制内容与通关方式。
